# バグ修正 要件定義書

## Introduction（概要）

ToDo リストアプリ（`bugfix_workflow/todo-app`）において、入力欄が空欄（または空白文字のみ）の状態で「追加」ボタンを押しても、中身のないタスクがリストに追加されてしまうバグを修正する。

本来、タスクは意味のあるテキストを持つべきであり、空のタスクはリストを乱雑にし、残り件数の表示も不正確になる。この修正により、空欄・空白のみの入力では何も追加されないようにする。

加えて、この修正の一部として以下の 2 点を扱う。
- **保存値の trim（正規化）**: 空でない入力を追加する際は、前後の空白を除去した（trim 済みの）テキストをタスクとして保存する（従来は生の入力文字列をそのまま保存していた）。
- **空入力時の視覚的フィードバック**: 空欄・空白のみで「追加」を押したときは、タスクを追加しないことに加えて、入力欄を軽く強調する視覚的フィードバック（一時的なハイライトやシェイクなどの軽微な演出）を表示する。

上記以外の既存の切り替え・削除・件数表示・永続化の動作は一切変更しない。

本要件は **バグ #1（空欄でもタスクが追加できてしまう）のみ** を対象とする。対象ファイルは `bugfix_workflow/todo-app`（`app.js`, `style.css`, `index.html`）。

## Bug Analysis（バグ分析）

### Current Behavior (Defect)（現在の挙動：不具合）

入力欄が空、または空白文字のみの状態で「追加」ボタンを押したときに、中身のないタスクが追加されてしまう。

1.1 WHEN 入力欄が空文字のまま「追加」ボタンを押す THEN システムは 空のタスクをリストに追加してしまう
1.2 WHEN 入力欄が半角・全角スペースやタブなど空白文字のみの状態で「追加」ボタンを押す THEN システムは 空白のみのタスクをリストに追加してしまう

### Expected Behavior (Correct)（期待する挙動：正しい動作）

入力欄が空、または空白文字のみのときは、タスクを一切追加せず、入力欄を軽く強調する視覚的フィードバックを表示する。また、空でない入力を追加する際は、前後の空白を除去した（trim 済みの）テキストをタスクとして保存する。

2.1 WHEN 入力欄が空文字のまま「追加」ボタンを押す THEN システムは SHALL タスクを追加せず、リストと残り件数を変化させない
2.2 WHEN 入力欄が空白文字のみの状態で「追加」ボタンを押す THEN システムは SHALL タスクを追加せず、リストと残り件数を変化させない
2.3 WHEN 入力欄が空または空白文字のみの状態で「追加」ボタンを押す THEN システムは SHALL 入力欄に一時的なハイライトやシェイクなどの軽微な視覚的フィードバックを表示する
2.4 WHEN 前後に空白を含む空でないテキスト（例: 「 買い物 」）を入れて「追加」ボタンを押す THEN システムは SHALL 前後の空白を除去した trim 済みテキスト（例: 「買い物」）をタスクとして保存する

### Unchanged Behavior (Regression Prevention)（変更してはいけない挙動：デグレ防止）

空欄でない通常の入力に対する既存の動作は、以下のとおり維持する。なお、保存値の trim 化（2.4）に伴い、前後に空白を含む入力の「保存されるテキスト」だけは意図的に変更される点に留意する（前後の空白を含まない入力は従来どおり同じ値が保存される）。

3.1 WHEN 前後に空白を含まない空白でないテキストを入れて「追加」ボタンを押す THEN システムは SHALL CONTINUE TO そのテキストのタスクをリストに追加する
3.2 WHEN タスクのチェックボックスを操作する THEN システムは SHALL CONTINUE TO 完了／未完了を切り替える
3.3 WHEN 「×」ボタンを押す THEN システムは SHALL CONTINUE TO そのタスクだけを削除する
3.4 WHEN 未完了タスクが存在する THEN システムは SHALL CONTINUE TO 残り件数を表示する
3.5 WHEN ブラウザをリロードする THEN システムは SHALL CONTINUE TO 保存済みのタスクを復元して表示する

## Bug Condition（バグ条件の導出）

要件から導出したバグ条件とプロパティを以下に示す。

**バグ条件関数** — バグを引き起こす入力を識別する:

```pascal
FUNCTION isBugCondition(X)
  INPUT: X of type TaskInput   // 入力欄の生の文字列
  OUTPUT: boolean

  // 前後の空白を取り除いた結果が空文字なら、バグを引き起こす入力
  RETURN trim(X.text) = ""
END FUNCTION
```

**プロパティ仕様（Fix Checking）** — バグ条件を満たす入力に対する正しい動作:

```pascal
// Property: Fix Checking - 空入力ではタスクを追加せず、視覚的フィードバックを出す
FOR ALL X WHERE isBugCondition(X) DO
  before ← todos の件数
  F'(X)                          // 修正後の追加処理を実行
  after ← todos の件数
  ASSERT after = before          // 件数が変化しない（追加されない）
  ASSERT feedbackShown(input)    // 入力欄に軽微な視覚的フィードバックが表示される
END FOR
```

```pascal
// Property: Fix Checking - 空でない入力は trim 済みテキストで保存される
FOR ALL X WHERE NOT isBugCondition(X) DO
  F'(X)                          // 修正後の追加処理を実行
  saved ← 追加されたタスクの text
  ASSERT saved = trim(X.text)    // 前後の空白を除去した値が保存される
END FOR
```

**プリザベーション目標（Preservation Checking）** — バグ条件を満たさない入力では、保存値の trim 化を除き挙動を変えない:

```pascal
// Property: Preservation Checking - 通常入力の挙動は（保存値の正規化を除き）不変
FOR ALL X WHERE NOT isBugCondition(X) DO
  // 保存されるテキストは trim(X.text) に正規化される（意図的な変更）。
  // それ以外（追加が成功すること、件数の増加、並び替え、永続化など）は F と同一。
  ASSERT F'(X) = F(X) を「保存 text を trim(X.text) に置き換えた期待結果」と比較して同一
END FOR
```

**定義:**
- **F**: 修正前の追加処理（現在のコード）
- **F'**: 修正後の追加処理
- **C(X)**: `trim(X.text) = ""`（空欄・空白のみの入力）
- **trim 化の影響**: `NOT C(X)` かつ前後に空白を含む入力では、保存値が `trim(X.text)` に正規化されるため、この 1 点のみ F と F' で結果が異なる（意図した変更）
- **反例**: 入力欄が空のまま「追加」→ 空タスクが追加される／「 買い物 」を追加 → 前後の空白付きのまま保存される
