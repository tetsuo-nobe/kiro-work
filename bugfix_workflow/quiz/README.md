# ミニクイズ — BugFix workflow 体験キット（4）

Kiro の BugFix モードを体験するための練習用プロジェクトです。
このアプリには **意図的に 4 つのバグ** が仕込まれています。
Kiro と対話しながら、1 つずつ原因を突き止めて直してみましょう。

## アプリの起動方法

ビルドは不要です。`index.html` をブラウザで開くだけで動きます。

- `index.html` をダブルクリックする、または
- VS Code の拡張機能「Live Server」などで開く

## このアプリの正しい仕様

- 全 4 問のクイズを 1 問ずつ表示する
- 選択肢を選ぶと次の問題へ進む
- **全 4 問**を出題し終えると結果画面に切り替わる
- 正解を選んだ問題の数だけスコアが加算される
- 結果画面では「正解数 / 全問数」と「正答率（%）」を表示する
  - 例: 4 問中 4 問正解なら「4 / 4 問正解」「正答率 100%」
- 「もう一度」を押すと、スコアも進捗も **最初からやり直せる**

## バグ一覧

> バグ #1 を先に直すと、#2（正答率）の症状が確認しやすくなります。#4 は単体で再現します。

### バグ #1 正解を選んでもスコアが増えない 

- **再現手順**: どの問題でも正解の選択肢を選び、最後まで進めて結果を見る
- **現在の症状**: 全部正解しても「0 / 4 問正解」になる
- **期待する動作**: 正解した数だけスコアが増える
- **ヒント**: 選択肢が選ばれたときの処理（`selectAnswer`）で、正解判定 `choiceIndex === q.answer` がうまくいっていません。`selectAnswer` に渡ってくる値が **何型か**（数値か文字列か）を確認してみましょう。`===`（厳密等価）は型が違うと一致しません

### バグ #2 正答率がいつも 0% になる 

- **再現手順**: （バグ #1 を直したあと）何問か正解して結果を見る
- **現在の症状**: 正解しているのに「正答率 0%」と表示される
- **期待する動作**: 正解数に応じた正答率が表示される（例: 4 問中 2 問で 50%）
- **ヒント**: 正答率の計算式のカッコの位置を確認しましょう。`score / (questions.length * 100)` は「何を何で割っているか」を考えると、意図とずれているはずです

### バグ #3 最後の問題が出題されない 

- **再現手順**: クイズを最後まで進める。問題番号の表示に注目する
- **現在の症状**: 第 3 問まで答えると結果画面に飛んでしまい、**第 4 問が表示されない**
- **期待する動作**: 全 4 問が出題されてから結果画面になる
- **ヒント**: 次の問題へ進むときの条件（`currentIndex < questions.length - 1`）を確認しましょう。この `- 1` があることで、最後の 1 問に届く前に結果へ進んでいます。これは典型的な「オフバイワン（1 個ずれ）」エラーです

### バグ #4 「もう一度」を押しても最初からやり直せない 

- **再現手順**: クイズを最後まで進めて結果画面を出し、「もう一度」を押す
- **現在の症状**: 第 1 問に戻らず、**最後の問題が表示されたまま** になる（スコアも 0 に戻っていない）
- **期待する動作**: 「もう一度」で第 1 問から、スコア 0 でやり直せる
- **ヒント**: リセット処理（`retry`）は画面の切り替えはしていますが、状態変数を戻しているでしょうか。このアプリの進行は **問題番号（`currentIndex`）** と **スコア（`score`）** の 2 つの状態で管理されています。`retry` がそれらを初期値に戻しているか確認しましょう
- **補足**: このバグは他のバグと独立して再現します。まず単体で直してみて、そのあと #1〜#3 も直すと、全体が正しく最初からやり直せるようになります

## Kiro の Bug Fix ワークフローで直してみよう

この演習では、Kiro の **Bug Fix ワークフロー**（Spec の一種。バグ修正を「根本原因の分析 → 修正設計 → 実装」の 3 段階で進める機能）を使って、上のバグを 1 つずつ直します。

### 1. Bug Fix ワークフローを開始する

次のいずれかの方法で始めます。

- 新しいセッションの「Let's build」画面で **「Bug Fix」** を選ぶ
- または Kiro パネルの **Specs** の **「＋」** を押し、Kiro に聞かれたら **「Bug」** を選ぶ
- すでにセッション中なら、チャット入力欄の下にある **エージェント名をクリック → 「Bug Fix」** に切り替える

### 2. バグを説明する（この 4 点を伝えると精度が上がります）

Bug Fix ワークフローは、次の 4 点がそろうとうまく機能します。上のバグ一覧からそのまま書き写せます。

1. **再現手順**: どう操作すると起きるか
2. **現在の症状**: いま何が起きているか
3. **期待する動作**: 本来どうあるべきか
4. **変えてはいけないこと**: 直すついでに壊してほしくない挙動

#### 依頼の例（バグ #3 最後の問題が出ないの場合）

> クイズアプリにバグがあります。
> - 再現手順: クイズを最後まで進める
> - 現在の症状: 第 3 問まで答えると結果画面に飛び、第 4 問が表示されない
> - 期待する動作: 全 4 問が出題されてから結果画面になる
> - 変えてはいけないこと: 問題の表示や選択肢の動作、結果画面への切り替え自体はそのまま
>
> このバグを Bug Fix ワークフローで直してください。

### 3. 3 つのフェーズを確認しながら進める

Kiro は次の順にドキュメントを作り、各段階で確認を求めてきます。内容を読み、必要なら「ここはこうして」と修正依頼を出してから次へ進みましょう。

1. **`bugfix.md`（分析）**: 現在の挙動・期待する挙動・変えない挙動を整理
2. **`design.md`（設計）**: 根本原因の特定と修正方針、確認すべきテスト観点
3. **`tasks.md`（実装）**: 実際の修正とリグレッション（他を壊していないか）を防ぐテスト

生成物は `.kiro/specs/<バグの名前>/` に保存されます。

### 4. 直ったことを確認して、次のバグへ

修正後にアプリを動かし、README の「期待する動作」どおりになったか確かめます。1 つ直したら次のバグへ。バグごとに Bug Fix ワークフローを回すのがおすすめです。

> 補足: バグ #1（加点されない）を直すと #2（正答率）の症状が見えやすくなるなど、バグ同士が関係することがあります。「変えてはいけないこと」に既に直したバグの動作を書いておくと、Bug Fix ワークフローがリグレッション（せっかく直した所を再び壊すこと）を防いでくれます。

答え合わせをしたくなったら `SOLUTION.md` を見てください。
（自力で挑戦したい場合は、先に見ないのがおすすめです）
