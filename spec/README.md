# Kiro IDE Spec セッション ハンズオン: 国別統計アプリを構造的に作ろう �📊

## 概要

Kiro の Spec セッション（構造化ワークフロー）を使って、国を選択するとその国の統計情報を表示するWebアプリを作成します。Spec セッションでは「要件定義 → 設計 → タスク分解 → 実装」という段階的なプロセスを体験できます。

**完成イメージ**: プルダウンから国を選択すると、World Bank（世界銀行）の公開APIから人口・GDP などの統計情報を取得して表示するWebアプリ（localhost:8080 で動作）

**前提条件**:
- Kiro がインストール済みであること
- Node.js がインストール済みであること（HTTPサーバー用）
- 基本的なKiroの画面操作ができること
- （推奨）先に Vibe コーディングハンズオンを体験済みであること

> 💡 **なぜ「国別統計アプリ」なのか**: 天気アプリは「都市名 → 緯度経度変換（Geocoding）→ グリッドポイント取得 → 天気取得」と API を何段も連鎖させる必要があり、題材としては複雑でした。国別統計アプリなら「国を選択 → 1回 API を呼ぶ → 表示」というシンプルな流れになり、Spec セッションの学習そのものに集中できます。

---

## Vibe セッションとの違い

| 観点 | Vibe セッション | Spec セッション |
|------|------|------|
| 進め方 | 会話しながら即座にコード生成 | 要件→設計→タスク→実装の段階的プロセス |
| 適したケース | 小規模・プロトタイプ・実験 | 中〜大規模・チーム開発・品質重視 |
| 成果物 | コードのみ | 要件書 + 設計書 + タスク一覧 + コード |
| 変更管理 | 会話履歴に依存 | 仕様書として残る |

## ハンズオン手順

---

### ステップ 0: ワークスペースの準備

1. 任意の場所に空のフォルダを作成します（例: `country-stats-app`）
1. Kiro でそのフォルダを開きます（File → Open Folder）
1. Kiro の上部に「**Manage**」のリンクが表示された場合は、そのリンクをクリックして「**Trust**」をクリックして、そのダイアログを閉じます。


### ステップ 1: Spec セッションの開始

1. 「Let's build」で **Spec** を選択します
1. プロンプト入力欄に以下を入力します:

   ```
   ユーザーがプルダウンから国を選択すると、その国の統計情報（人口・GDPなど）を見栄え良く表示するシンプルなWebアプリを作成してください。国の一覧と統計情報は、World Bank（世界銀行）の公開API（api.worldbank.org）から取得してください。このAPIはAPIキー不要・CORS対応で、format=json を指定するとJSONを返します。HTMLとJavaScriptを使用してアプリを構築してください。また、シェルスクリプトを実行してlocalhost:8080でHTTPサーバーを起動することでホストしてください。プロジェクトのタスク数は最小限にして15分以内にすべてのタスク実行が完了することを目標とします。
   ```

1. Enter を押して送信します。

---

### ステップ 2: 要件定義の確認

* Kiro が自動的に要件（Requirements）を生成します。

1. Kiro からの問い合わせがある場合は回答します。
    - 新機能としての開発 (Build a feature) か、既存アプリのバグ修正か (Fix a Bug) 等
    - 要件定義 (Requirements) から始めるか、技術設計 (Technical Design) から始めるか等
1. Kiro がツールへのアクセスやコマンドの実行を行うときに、「**Allow**」または「**Always allow**」を選択します。
    - Allow ：この段階では OK とする
    - Always allow：以後も暗黙的に OK とする。
        - コマンドの場合、さらにどこまで許可するかの確認が求められる場合があります。
1. `.kiro/specs/` フォルダ内に要件ドキュメントが作成されるのを確認します
1. 要件の内容を確認しましょう。以下のような項目が含まれているはずです:
   - ユーザーがプルダウンから国を選択できること
   - 国の一覧を World Bank API から取得すること
   - 選択した国の統計情報を World Bank API から取得すること
   - 統計情報を画面に表示すること
   - localhost:8080 でホストすること

1. 要件に問題がなければ、Kiro の提案を承認して次の Design へ進みます。
    - Kiro で「**→ Continue**」- 「**Generate Design**」をクリックします。（もしくは、チャットで「次へ進んで」と指示します。）

> 💡 **ポイント**: Spec セッションでは、いきなりコードを書くのではなく、まず「何を作るか」を明確にします。要件に不足や誤りがあれば、この段階でフィードバックできます。

---

### ステップ 3: 設計の確認

要件が確定すると、Kiro が設計（Design）を生成します。

1. 設計ドキュメントを確認します。以下のような内容が含まれます:
   - 使用するAPI（World Bank API: api.worldbank.org）
   - ファイル構成（HTML、JavaScript、起動スクリプト）
   - データフロー（国一覧の取得 → プルダウン表示 → 国選択 → 統計取得 → 表示）
   - エラーハンドリング方針

2. 設計内容を確認し、承認して次の Task list へ進みます。
    - Kiro で「**→ Continue**」- 「**Generate Tasks**」をクリックします。（もしくは、チャットで「次へ進んで」と指示します。）


> 💡 **ポイント**: 設計段階で技術的な方針が決まります。「このAPIで本当に大丈夫か？」「ファイル構成はこれでいいか？」をチームでレビューできるのが Spec セッションの強みです。

---

### ステップ 4: タスク一覧の確認

設計が確定すると、Kiro が実装タスク（Tasks）を生成します。

1. タスク一覧を確認します。以下のようなタスクに分解されているはずです:
   - HTMLファイルの作成（UI構築・プルダウン配置）
   - JavaScript の実装（国一覧取得・統計取得ロジック）
   - HTTPサーバー起動スクリプトの作成
   - エラーハンドリングの実装

2. タスクの順序や粒度を確認し、問題なければ承認します

> 💡 **ポイント**: タスクが明確に分かれているので、「今どこまで進んでいるか」が一目でわかります。大規模プロジェクトでは、この可視性が非常に重要です。

---

### ステップ 5: 実装の実行

タスクが確定したら、Kiro に実装を開始させます。

* **時間がかかる場合があります。また Free Plan の場合クレジットが不足する可能性があることをご了承ください。**

1. タスク一覧から最初のタスクを選択し、実装を開始します
2. Kiro が各タスクを順番に実装していくのを確認します
3. 各タスク完了時に、生成されたコードを確認できます

生成されるファイルの例:
- `index.html` - メインのWebページ（国選択プルダウン）
- `app.js` または `<script>` タグ内 - 国一覧・統計取得ロジック
- `start-server.sh` - HTTPサーバー起動スクリプト

---

### ステップ 6: 動作確認

1. 生成された起動スクリプト（`start-server.sh` など）を確認します
2. Kiro のターミナル、またはコマンドプロンプトでサーバーを起動します:

```
./start-server.sh
```

3. ブラウザで `http://localhost:8080` にアクセスします
4. プルダウンから国（例: `Japan`, `United States`, `Germany`）を選択して統計情報が表示されることを確認します

> 💡 **ポイント**: World Bank API は無料・APIキー不要で利用できる公開APIです。世界中の国の統計が対象なので、天気アプリと違い「国内限定」といった制約がありません。

---

### ステップ 7: 振り返り

ハンズオンのまとめとして、Spec セッションで体験したプロセスを振り返ります:

| フェーズ | 内容 | メリット |
|------|------|------|
| 要件定義 | 何を作るかを明文化 | 認識のズレを防ぐ |
| 設計 | どう作るかを決定 | 技術的リスクを早期発見 |
| タスク分解 | 作業を細分化 | 進捗が可視化される |
| 実装 | タスクに沿ってコード生成 | 一貫性のある実装 |

## 補足説明

### World Bank API について

- エンドポイント: `https://api.worldbank.org/v2`
- APIキー: 不要（公開API）
- CORS: 対応（ブラウザから直接呼び出し可能）
- レスポンス形式: `?format=json` を付けると JSON を返す（省略時は XML）
- 対象: 世界中の国・地域
- データ更新: 世界銀行が集計した公式統計（更新日は `lastupdated` フィールドで確認可能）

> ⚠️ **レスポンス形式の注意**: World Bank API の JSON レスポンスは `[メタ情報, データ配列]` という2要素の配列で返ります。1番目にページング情報、2番目に実データが入っているため、JavaScript 側では `data[1]` を参照してデータを取り出します。

### 主なエンドポイント

国の一覧を取得（ページングあり）:

```
https://api.worldbank.org/v2/country?format=json&per_page=300
```

指定した国の統計を取得（`{iso3}` は ISO3 国コード、`{indicator}` は指標コード、`mrv=1` は最新1件）:

```
https://api.worldbank.org/v2/country/{iso3}/indicator/{indicator}?format=json&mrv=1
```

例（日本の人口の最新値）:

```
https://api.worldbank.org/v2/country/JPN/indicator/SP.POP.TOTL?format=json&mrv=1
```

### 代表的な指標コード（indicator）

| 指標コード | 内容 |
|------|------|
| `SP.POP.TOTL` | 総人口 |
| `NY.GDP.MKTP.CD` | GDP（米ドル） |
| `NY.GDP.PCAP.CD` | 一人あたりGDP（米ドル） |
| `SP.DYN.LE00.IN` | 平均寿命（歳） |

### 想定される技術的な流れ

1. ページ読み込み時に国一覧（`/v2/country`）を取得し、プルダウンに国名を並べる
2. ユーザーがプルダウンから国を選択
3. 選択された国の ISO3 コードを使い、各指標（人口・GDPなど）を `/v2/country/{iso3}/indicator/{indicator}` で取得
4. 取得した値（`data[1][0].value`）を整形して画面に表示

### FAQ

| 質問 | 回答 |
|------|------|
| Spec の各フェーズは必ず承認が必要？ | はい。各フェーズで内容を確認し、フィードバックや修正を入れられるのが Spec セッションの特徴 |
| 要件を後から変更できる？ | できる。要件を修正すると、設計やタスクも再生成される |
| Spec で作った仕様書はどこに保存される？ | `.kiro/specs/` フォルダ内にMarkdownファイルとして保存される。Git管理も可能 |
| APIキーが必要なAPIは使えない？ | 使えるが、ハンズオンでは事前準備の手間を避けるため、キー不要のAPIを選択している |
| 国によってデータが無いことがある？ | ある。統計が未整備の国・年では値が `null` になることがあるため、その場合は「データなし」と表示する想定 |

### トラブルシューティング

| 症状 | 対処 |
|------|------|
| サーバーが起動しない | Node.js がインストールされているか確認。`node --version` で確認 |
| 統計情報が取得できない | ネットワーク接続を確認。api.worldbank.org へのアクセスが可能か確認 |
| JSON が取得できず XML が返る | URL に `?format=json` が付いているか確認 |
| データが `undefined` になる | レスポンスが `[メタ情報, データ配列]` の形のため、`data[1]` を参照しているか確認 |
| 値が `null` で表示される | その国・年に統計が無いケース。別の国を選ぶか「データなし」表示にする |
| Spec が生成されない | Spec セッションで開始しているか確認。Vibe セッションでは Spec は生成されない |

## 参考: Spec セッションで生成される成果物

```
.kiro/
└── specs/
    └── country-stats-app/     （または Kiro が命名したフォルダ）
        ├── requirements.md    ← 要件定義
        ├── design.md          ← 設計書
        └── tasks.md           ← タスク一覧（チェックリスト形式）
```

これらのファイルはプロジェクトの一部として Git で管理でき、チームメンバーとの共有やレビューに活用できます。
