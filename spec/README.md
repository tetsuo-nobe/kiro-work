# Kiro IDE Spec モード ハンズオン: 天気アプリを構造的に作ろう 🌤️🏙️

## 概要

Kiro の Spec セッション（構造化ワークフロー）を使って、アメリカの都市の天気情報を表示するWebアプリを作成します。Spec モードでは「要件定義 → 設計 → タスク分解 → 実装」という段階的なプロセスを体験できます。

**完成イメージ**: 都市名を入力すると、アメリカ政府の公開APIから天気情報を取得して表示するWebアプリ（localhost:8080 で動作）

**前提条件**:
- Kiro がインストール済みであること
- Node.js がインストール済みであること（HTTPサーバー用）
- 基本的なKiroの画面操作ができること
- （推奨）先に Vibe コーディングハンズオンを体験済みであること

---

## Vibe モードとの違い

| 観点 | Vibe モード | Spec モード |
|------|------|------|
| 進め方 | 会話しながら即座にコード生成 | 要件→設計→タスク→実装の段階的プロセス |
| 適したケース | 小規模・プロトタイプ・実験 | 中〜大規模・チーム開発・品質重視 |
| 成果物 | コードのみ | 要件書 + 設計書 + タスク一覧 + コード |
| 変更管理 | 会話履歴に依存 | 仕様書として残る |

## 言語使用規則

### ユーザーコミュニケーション
- 日本語で質問された場合は必ず日本語で回答する
- 技術的な説明も日本語で行い、必要に応じて英語の技術用語を併記する
- エラーメッセージや警告は日本語で表示する

### ドキュメント作成
- 仕様書・設計書は日本語で記述する
- README、API ドキュメントは日本語を優先する
- コードコメントは日本語で記述する
- 変更履歴やコミットメッセージは日本語で記述する

### コード規約
- 変数・関数・クラス名: 英語を使用（国際的な標準に準拠）
- コメント: 日本語で記述し、コードの意図を明確に説明する
- 外部ライブラリ・API: 英語名をそのまま使用する
- 定数・設定値: 英語名を使用し、コメントで日本語説明を追加する

### 技術用語の扱い
- 一般的な技術用語は英語のまま使用（例：API、JSON、HTTP）
- 日本語訳が不自然な場合は英語を優先し、必要に応じて日本語説明を併記する

### ログ・デバッグ出力
- ユーザー向けメッセージ: 日本語必須
- エラーハンドリング: ユーザーに表示されるメッセージは日本語で記述する

### ステップ 2: Spec セッションの開始

1. Kiro の左サイドバーまたはコマンドパレットから **新しい Spec セッション** を開始します
2. プロンプト入力欄に以下を入力します:

```
ユーザーがアメリカ合衆国の都市名を入力すると、現在の天気状況を表示するシンプルな天気アプリを作成してください。天気情報と都市名は、公開されている政府ウェブサイトから取得してください。HTMLとJavaScriptを使用してアプリを構築し、Windowsコマンドプロンプトスクリプトを実行してlocalhost:8080でHTTPサーバーを起動することでホストしてください。
```

3. Enter を押して送信します。

---

### ステップ 3: 要件定義の確認

Kiro が自動的に要件（Requirements）を生成します。

1. `.kiro/specs/` フォルダ内に要件ドキュメントが作成されるのを確認します
2. 要件の内容を確認しましょう。以下のような項目が含まれているはずです:
   - ユーザーが都市名を入力できること
   - 天気情報を政府API（National Weather Service API）から取得すること
   - 天気情報を画面に表示すること
   - localhost:8080 でホストすること

3. 要件に問題がなければ、Kiro の提案を承認（Accept）します

> 💡 **ポイント**: Spec モードでは、いきなりコードを書くのではなく、まず「何を作るか」を明確にします。要件に不足や誤りがあれば、この段階でフィードバックできます。

---

### ステップ 4: 設計の確認

要件が確定すると、Kiro が設計（Design）を生成します。

1. 設計ドキュメントを確認します。以下のような内容が含まれます:
   - 使用するAPI（National Weather Service API: api.weather.gov）
   - ファイル構成（HTML、JavaScript、起動スクリプト）
   - データフロー（ユーザー入力 → API呼び出し → 表示）
   - エラーハンドリング方針

2. 設計内容を確認し、問題なければ承認します

> 💡 **ポイント**: 設計段階で技術的な方針が決まります。「このAPIで本当に大丈夫か？」「ファイル構成はこれでいいか？」をチームでレビューできるのが Spec モードの強みです。

---

### ステップ 5: タスク一覧の確認

設計が確定すると、Kiro が実装タスク（Tasks）を生成します。

1. タスク一覧を確認します。以下のようなタスクに分解されているはずです:
   - HTMLファイルの作成（UI構築）
   - JavaScript の実装（API連携ロジック）
   - HTTPサーバー起動スクリプトの作成
   - エラーハンドリングの実装

2. タスクの順序や粒度を確認し、問題なければ承認します

> 💡 **ポイント**: タスクが明確に分かれているので、「今どこまで進んでいるか」が一目でわかります。大規模プロジェクトでは、この可視性が非常に重要です。

---

### ステップ 6: 実装の実行

タスクが確定したら、Kiro に実装を開始させます。

* **今回は時間とクレジットの節約のため、実施しません。**

1. タスク一覧から最初のタスクを選択し、実装を開始します
2. Kiro が各タスクを順番に実装していくのを確認します
3. 各タスク完了時に、生成されたコードを確認できます

生成されるファイルの例:
- `index.html` - メインのWebページ
- `app.js` または `<script>` タグ内 - 天気取得ロジック
- `start-server.bat` - HTTPサーバー起動スクリプト

---

### ステップ 7: 動作確認

1. 生成された起動スクリプト（`start-server.bat` など）を確認します
2. Kiro のターミナル、またはコマンドプロンプトでサーバーを起動します:

```
start-server.bat
```

3. ブラウザで `http://localhost:8080` にアクセスします
4. 都市名（例: `New York`, `Los Angeles`, `Chicago`）を入力して天気情報が表示されることを確認します

> 💡 **ポイント**: National Weather Service API は無料・APIキー不要で利用できる政府公開APIです。ただし、アメリカ国内の都市のみ対応しています。

---

### ステップ 8: 振り返り

ハンズオンのまとめとして、Spec モードで体験したプロセスを振り返ります:

| フェーズ | 内容 | メリット |
|------|------|------|
| 要件定義 | 何を作るかを明文化 | 認識のズレを防ぐ |
| 設計 | どう作るかを決定 | 技術的リスクを早期発見 |
| タスク分解 | 作業を細分化 | 進捗が可視化される |
| 実装 | タスクに沿ってコード生成 | 一貫性のある実装 |

## 補足説明

### National Weather Service API について

- エンドポイント: `https://api.weather.gov`
- APIキー: 不要（公開API）
- 制限: アメリカ国内の地点のみ
- フロー: 都市名 → 緯度経度変換 → ポイント取得 → 天気予報取得

### 想定される技術的な流れ

1. ユーザーが都市名を入力
2. Geocoding で緯度・経度を取得（Census Geocoder API など）
3. `api.weather.gov/points/{lat},{lon}` でグリッドポイントを取得
4. グリッドポイントから天気予報を取得
5. 結果を画面に表示

### FAQ

| 質問 | 回答 |
|------|------|
| Spec の各フェーズは必ず承認が必要？ | はい。各フェーズで内容を確認し、フィードバックや修正を入れられるのが Spec モードの特徴 |
| 要件を後から変更できる？ | できる。要件を修正すると、設計やタスクも再生成される |
| Spec で作った仕様書はどこに保存される？ | `.kiro/specs/` フォルダ内にMarkdownファイルとして保存される。Git管理も可能 |
| APIキーが必要なAPIは使えない？ | 使えるが、ハンズオンでは事前準備の手間を避けるため、キー不要のAPIを選択している |

### トラブルシューティング

| 症状 | 対処 |
|------|------|
| サーバーが起動しない | Node.js がインストールされているか確認。`node --version` で確認 |
| 天気情報が取得できない | ネットワーク接続を確認。api.weather.gov へのアクセスが可能か確認 |
| 都市名が認識されない | 英語で正確な都市名を入力しているか確認（例: "New York" ○、"ニューヨーク" ×） |
| Spec が生成されない | Spec セッションモードで開始しているか確認。Vibe モードでは Spec は生成されない |

これらのファイルはプロジェクトの一部として Git で管理でき、チームメンバーとの共有やレビューに活用できます。
