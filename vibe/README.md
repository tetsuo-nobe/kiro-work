# Kiro IDE Vibeコーディング ハンズオン: AWSクイズアプリを作ろう 🎯☁️

## 概要

Kiro の Vibe セッション（会話型コーディング）を使って、AWSに関するインタラクティブなクイズアプリを作成します。

**完成イメージ**: AWSサービスに関する4択クイズが出題され、回答するとスコアが表示されるWebアプリ

**前提条件**:
- Kiro がインストール済みであること
- 基本的なKiroの画面操作（チャット欄への入力）ができること

---

## ハンズオン手順

---

### ステップ 0: ワークスペースの準備

1. 現在、Kiro を起動している場合はいったん閉じます。
1. デスクトップに空のフォルダを作成します（例: `aws-quiz-app`）
    - デスクトップをクリック、右クリックから新しいフォルダ作成を指定します。
1. デスクトップの Kiro のアイコンをクリックして Kiro を起動します
1. Kiro のメニューで、「**File**」-「**Open Folder...**」で作成したフォルダを選択して開きます


---

### ステップ 1: クイズアプリの生成


* チャット欄に以下のプロンプトを入力します:

```
AWSサービスに関する4択クイズアプリを作ってください。

要件:
- HTML/CSS/JavaScript の単一ファイル（index.html）で作成
- 全5問のクイズ（AWS の主要サービスに関する問題）
- 1問ずつ表示し、回答を選択すると正誤がわかる
- 全問回答後にスコアと結果サマリーを表示
- モダンで見栄えの良いUI（グラデーション背景、カード型デザイン、アニメーション付き）
- レスポンシブ対応
- 正解時と不正解時で異なるビジュアルフィードバック
```

* Kiro がコードを生成するのを待ちます。ファイルが作成されたら次のステップへ進みます。

* Kiro がツールへのアクセスやコマンドの実行を行うときに、「**Accept**」または「**Trust**」または「**Allow**」の応答を求めてきますので、応答します。
    - Accept や Allow：この段階では OK とする
    - Trust：以後も暗黙的に OK とする。
        - コマンドの場合、さらにどこまで許可するかの確認が求められる場合があります。
---

### ステップ 2: 動作確認

1. Kiro の左側のアイコンで、一番上にある「エクスプローラー」のアイコンをクリックします。
1. エクスプローラーで `index.html` を右クリック →「**Open Containing Folder**」または「**Reveal in File Explorer**」でフォルダを開きます
2. `index.html` をダブルクリックしてブラウザを開きます
3. クイズを実際にプレイしてみましょう！

> 💡 **ポイント**: たった1回の指示で、見栄えの良いアプリが完成しました。これが Vibe コーディングの威力です。

---

### (オプション) ステップ 3: 機能追加を依頼する

アプリが動いたら、追加の要望を自然言語で伝えてみましょう。以下のいずれか（または複数）を試してください:

#### 例 A: 問題数を増やす
```
クイズの問題を10問に増やしてください。AWS Lambda、DynamoDB、CloudFront、IAM、VPC に関する問題も追加してください。
```

#### 例 B: タイマー機能を追加
```
各問題に15秒の制限時間を追加してください。残り時間をプログレスバーで表示し、時間切れの場合は不正解扱いにしてください。
```

#### 例 C: 結果画面を強化
```
結果画面に以下を追加してください:
- 正答率に応じた称号（90%以上: AWS マスター、70%以上: AWS エンジニア、それ以下: AWS 見習い）
- 間違えた問題の一覧と正解の表示
- 「もう一度挑戦」ボタン
```

#### 例 D: デザインの変更
```
全体のカラーテーマをAWSのオレンジ（#FF9900）をアクセントカラーにしたデザインに変更してください。
```

---

### ステップ 4: プロジェクトのクローズと振り返り

* Kiro の「**File**」- 「**Close Folder**」を選択してプロジェクトを閉じます

ハンズオンのまとめとして、以下を確認します:

| 体験したこと | 学び |
|------|------|
| ステアリング設定 | プロジェクトのルールを事前に設定できる |
| Vibeコーディング | 自然言語の指示だけでアプリが完成する |
| 反復改善 | 追加要望も会話で伝えるだけで実装される |
| コード品質 | 日本語コメント付きの読みやすいコードが生成される |

## FAQ とトラブルシューティング

### FAQ

| 質問 | 回答 |
|------|------|
| ステアリングは必須？ | 必須ではないが、チーム開発では非常に有用。コーディング規約やプロジェクト固有のルールを共有できる |
| 生成されたコードは編集できる？ | もちろん。手動編集も可能だし、Kiro に修正を依頼することもできる |
| もっと複雑なアプリも作れる？ | Spec セッションを使えば、要件定義→設計→実装を段階的に進められる |

### トラブルシューティング

| 症状 | 対処 |
|------|------|
| ファイルが生成されない | Kiro のセッションが Vibe モードになっているか確認 |
| ブラウザで表示されない | ファイルパスが正しいか、HTMLの構文エラーがないか確認 |
| ステアリングが効かない | `.kiro/steering/` ディレクトリのパスとファイル名を確認。フロントマターの `inclusion: always` が正しく記述されているか確認 |
| 英語で応答される | ステアリングファイル作成後、新しいセッションを開始してみる |
