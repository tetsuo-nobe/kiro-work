# Kiro IDE Vibeコーディング ハンズオン: AWSクイズアプリを作ろう 🎯☁️

## 概要

Kiro の Vibe セッション（会話型コーディング）を使って、AWSに関するインタラクティブなクイズアプリを作成します。

**完成イメージ**: AWSサービスに関する4択クイズが出題され、回答するとスコアが表示されるWebアプリ

**前提条件**:
- Kiro がインストール済みであること
- 基本的なKiroの画面操作（チャット欄への入力）ができること

---

## ハンズオン手順

---

### ステップ 0: ワークスペースの準備

1. 任意の場所に空のフォルダを作成します（例: `aws-quiz-app`）
1. デスクトップの Kiro のアイコンをクリックして Kiro を起動します
1. サインイン方法として AWS Builder ID を選択してサインインを進めます
1. サインイン処理の最後で「Allow access」をクリックしてブラウザを閉じます
1. Kiro でセットアップ処理を続けます
1. 「Open a project」で作成したフォルダを開きます 

---

### ステップ 1: ステアリングの設定

ステアリングとは、Kiro に対して「プロジェクト全体で守ってほしいルール」を事前に伝える仕組みです。今回は「日本語で応答・コメントする」というルールを設定します。

チャット欄に以下を入力します:

```
グローバルのステアリングとして messages-in-japanese.md というファイルを作成して、以下の内容を書いてください:

---
inclusion: always
---

# 日本語プロジェクト開発ガイドライン

## 言語使用規則

### ユーザーコミュニケーション
- 日本語で質問された場合は必ず日本語で回答する
- 技術的な説明も日本語で行い、必要に応じて英語の技術用語を併記する
- エラーメッセージや警告は日本語で表示する

### ドキュメント作成
- 仕様書・設計書は日本語で記述する
- README、API ドキュメントは日本語を優先する
- コードコメントは日本語で記述する
- 変更履歴やコミットメッセージは日本語で記述する

### コード規約
- 変数・関数・クラス名: 英語を使用（国際的な標準に準拠）
- コメント: 日本語で記述し、コードの意図を明確に説明する
- 外部ライブラリ・API: 英語名をそのまま使用する
- 定数・設定値: 英語名を使用し、コメントで日本語説明を追加する

### 技術用語の扱い
- 一般的な技術用語は英語のまま使用（例：API、JSON、HTTP）
- 日本語訳が不自然な場合は英語を優先し、必要に応じて日本語説明を併記する

### ログ・デバッグ出力
- ユーザー向けメッセージ: 日本語必須
- エラーハンドリング: ユーザーに表示されるメッセージは日本語で記述する
```

Kiro の左側で Kiro のアイコンをクリックして、「AGENT STEERING & SKILLS」の 「Global」の下に `messages-in-japanese.md` が存在することを確認します。

> 💡 **ポイント**: これ以降、Kiro は日本語でコメントを書き、日本語で応答してくれるようになります。ステアリングはプロジェクト単位で設定でき、チーム全員で共有できます。

---

### ステップ 2: クイズアプリの生成

チャット欄に以下のプロンプトを入力します:

```
AWSサービスに関する4択クイズアプリを作ってください。

要件:
- HTML/CSS/JavaScript の単一ファイル（index.html）で作成
- 全5問のクイズ（AWS の主要サービスに関する問題）
- 1問ずつ表示し、回答を選択すると正誤がわかる
- 全問回答後にスコアと結果サマリーを表示
- モダンで見栄えの良いUI（グラデーション背景、カード型デザイン、アニメーション付き）
- レスポンシブ対応
- 正解時と不正解時で異なるビジュアルフィードバック
```

Kiro がコードを生成するのを待ちます。ファイルが作成されたら次のステップへ進みます。

---

### ステップ 3: 動作確認

1. エクスプローラーで `index.html` を右クリック →「Reveal in File Explorer」でフォルダを開く
2. `index.html` をブラウザにドラッグ＆ドロップして開く
3. クイズを実際にプレイしてみましょう！

> 💡 **ポイント**: たった1回の指示で、見栄えの良いアプリが完成しました。これが Vibe コーディングの威力です。

---

### (オプション) ステップ 4: 機能追加を依頼する

アプリが動いたら、追加の要望を自然言語で伝えてみましょう。以下のいずれか（または複数）を試してください:

#### 例A: 問題数を増やす
```
クイズの問題を10問に増やしてください。AWS Lambda、DynamoDB、CloudFront、IAM、VPC に関する問題も追加してください。
```

#### 例B: タイマー機能を追加
```
各問題に15秒の制限時間を追加してください。残り時間をプログレスバーで表示し、時間切れの場合は不正解扱いにしてください。
```

#### 例C: 結果画面を強化
```
結果画面に以下を追加してください:
- 正答率に応じた称号（90%以上: AWS マスター、70%以上: AWS エンジニア、それ以下: AWS 見習い）
- 間違えた問題の一覧と正解の表示
- 「もう一度挑戦」ボタン
```

#### 例D: デザインの変更
```
全体のカラーテーマをAWSのオレンジ（#FF9900）をアクセントカラーにしたデザインに変更してください。
```

---

### ステップ 5: プロジェクトのクローズと振り返り

* Kiro の「FIle」- 「Close Folder」を選択してプロジェクトを閉じます

ハンズオンのまとめとして、以下を確認します:

| 体験したこと | 学び |
|------|------|
| ステアリング設定 | プロジェクトのルールを事前に設定できる |
| Vibeコーディング | 自然言語の指示だけでアプリが完成する |
| 反復改善 | 追加要望も会話で伝えるだけで実装される |
| コード品質 | 日本語コメント付きの読みやすいコードが生成される |

## FAQ とトラベルシューティング

### FAQ

| 質問 | 回答 |
|------|------|
| ステアリングは必須？ | 必須ではないが、チーム開発では非常に有用。コーディング規約やプロジェクト固有のルールを共有できる |
| 生成されたコードは編集できる？ | もちろん。手動編集も可能だし、Kiro に修正を依頼することもできる |
| もっと複雑なアプリも作れる？ | Spec セッションを使えば、要件定義→設計→実装を段階的に進められる |

### トラブルシューティング

| 症状 | 対処 |
|------|------|
| ファイルが生成されない | Kiro のセッションが Vibe モードになっているか確認 |
| ブラウザで表示されない | ファイルパスが正しいか、HTMLの構文エラーがないか確認 |
| ステアリングが効かない | `.kiro/steering/` ディレクトリのパスとファイル名を確認。フロントマターの `inclusion: always` が正しく記述されているか確認 |
| 英語で応答される | ステアリングファイル作成後、新しいセッションを開始してみる |
